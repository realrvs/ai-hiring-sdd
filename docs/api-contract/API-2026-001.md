## 1. HR LLM Gateway API

### 1.1. POST /v1/mask
Токенизация PII перед отправкой в LLM.

Request:
~~~json
{
  "text": "Иван Иванов, ivan@example.com, работал в ООО Ромашка",
  "session_id": "sess-2026-042",
  "entities": ["PERSON", "EMAIL", "ORGANIZATION"]
}
~~~

Response:
~~~json
{
  "masked_text": "<CANDIDATE_NAME_1>, <EMAIL_1>, работал в <COMPANY_1>",
  "tokens": [
    {"token": "<CANDIDATE_NAME_1>", "type": "PERSON"},
    {"token": "<EMAIL_1>", "type": "EMAIL"},
    {"token": "<COMPANY_1>", "type": "ORGANIZATION"}
  ],
  "session_id": "sess-2026-042"
}
~~~

Errors:
- 400 - invalid input
- 503 - Token Vault unavailable (read-only mode)

### 1.2. POST /v1/unmask
Re-identification (только RBAC recruiter).

Request:
~~~json
{
  "masked_text": "<CANDIDATE_NAME_1> работал в <COMPANY_1>",
  "session_id": "sess-2026-042",
  "role": "recruiter"
}
~~~

Response:
~~~json
{
  "text": "Иван Иванов работал в ООО Ромашка",
  "audit_id": "audit-2026-042-001"
}
~~~

Errors:
- 403 - role not allowed
- 404 - token not found
- 503 - Token Vault unavailable

### 1.3. POST /v1/budget/check
Проверка бюджета агента.

Request:
~~~json
{
  "agent_id": "screening-bg-001",
  "latency_class": "background",
  "batch_size": 10
}
~~~

Response:
~~~json
{
  "allowed": true,
  "max_cu": 1.0,
  "max_iterations": 30,
  "max_tokens": 200000,
  "max_wall_time_sec": 900,
  "remaining_cu": 0.62
}
~~~

Errors:
- 429 - budget exceeded -> Diagnosis Report

## 2. Consent API

### 2.1. POST /v1/consent/revoke
Hard trigger при отзыве согласия.

Request:
~~~json
{
  "candidate_id": "cand-2026-042",
  "reason": "right_to_be_forgotten",
  "channel": "api"
}
~~~

Response:
~~~json
{
  "status": "revoked",
  "triggered_at": "2026-10-07T10:00:00Z",
  "purge_sla_hours": 4,
  "audit_id": "audit-consent-2026-042"
}
~~~

Side effects:
- Метка consent-revoked на всех артефактах (<5 мин).
- Circuit Breaker: остановка пайплайнов.
- Purge Pipeline запущен.

### 2.2. GET /v1/consent/status/{candidate_id}
Response:
~~~json
{
  "candidate_id": "cand-2026-042",
  "consent_active": true,
  "ttl_expires_at": "2027-04-07T00:00:00Z",
  "purge_scheduled": false
}
~~~

~~~json
    {"candidate_id": "cand-001", "tokenized_text": "..."},
~~~

~~~json
{
  "results": [
    {
      "candidate_id": "cand-001",
      "score": 0.87,
      "risks": ["пробел в опыте 6 мес", "нет опыта с Kafka"],
~~~

Errors:
- 422 - batch_size > 10 (кроме no-batch)
- 429 - CU exceeded -> Diagnosis Report

## 5. Bias Detection API

### 5.1. POST /v1/bias/check
Request:
~~~json
{
  "stage": "screening",
  "diff_ids": ["cand-001", "cand-002"],
  "repository_id": "hiring-2026"
}
~~~

Response:
~~~json
{
  "fairness_score_diff": 0.94,
  "fairness_score_cumulative": 0.91,
  "thresholds": {"diff": 0.85, "cumulative": 0.80},
  "incidents": [],
  "label_applied": null
}
~~~

Side effects:
- Если diff < 0.85 -> метка bias-risk.
- Если cumulative < 0.80 -> задача tech-debt:bias-audit.

## 7. Общие конвенции

| Параметр | Значение |
|---|---|
| Auth | OAuth 2.0 / JWT |
| RBAC | recruiter, hrbp, dpo, admin |
| Rate limiting | 100 req/min per role |
| Idempotency | Idempotency-Key header |
| Versioning | URL path /v1/ |
| Audit | Все вызовы логируются в Audit Vault |
| Errors | RFC 7807 Problem Details |

## 8. Критерии приемки API-Contract
- [ ] Все endpoints покрыты OpenAPI-схемой.
- [ ] RBAC проверен для unmask и purge.
- [ ] Rate limiting настроен.
- [ ] Audit логирование включено.
- [ ] Согласовано с ИБ и DPO.
