# SPECS: AI Hiring Blueprint

## Метаданные
- ID: SPEC-2026-001
- Версия: 1.0
- Статус: Approved
- Связан с: PROP-2026-001

## 1. Функциональные требования

### FR-1: Три фазы зрелости
- FR-1.1: Система поддерживает режимы Assist / Augment / Autonomous.
- FR-1.2: Переход между фазами - только через Gate с метриками (2 квартала, 100% Purge SLA, 0 критических инцидентов).
- FR-1.3: Попытка перехода Фаза 1 -> Фаза 3 блокируется на уровне Policy Enforcement.

### FR-2: Конвейер найма
- FR-2.1: Этапы: Intake -> Sourcing -> Screening -> Interview -> Offer -> Onboard.
- FR-2.2: Каждый этап создает артефакт в Git (hiring/*-YYYY-NNN.md).
- FR-2.3: Каждый этап завершается Self-Check Report.
- FR-2.4: Изменение JD после старта скрининга -> пересмотр всех кандидатов.

### FR-3: Fast-Track и Hotfix
- FR-3.1: Fast-Track активируется меткой fast-track, критерии проверяются Gitea Actions автоматически.
- FR-3.2: Если критерии не выполнены - метка снимается, заявка блокируется.
- FR-3.3: Hotfix активируется только HRD/CEO, обязательна Consent-проверка.
- FR-3.4: После Hotfix - Post-Mortem с созданием JD/Scorecard.

### FR-4: Budget Enforcement
- FR-4.1: Фоновый агент: max 1.0 CU / батч, 30 iterations, 200k tokens, 15 мин.
- FR-4.2: Интерактивный агент: max 0.02 CU, 5 iterations, 5k tokens, 5 сек.
- FR-4.3: Превышение -> остановка + Diagnosis Report.
- FR-4.4: Бюджет - enforcement на уровне Agent Platform, не рекомендация.

### FR-5: Fallback
- FR-5.1: Уровень 1 (GigaChat 3.5 Ultra) -> Уровень 2 (Lightning) при error rate >5%, latency >30s, GPU util >90%.
- FR-5.2: Уровень 2 -> Уровень 3 (Human) при error rate >10%, latency >60s.
- FR-5.3: Circuit Breaker: 15 мин недоступности -> открытие, 5 мин после восстановления -> закрытие.

### FR-6: Bias Detection
- FR-6.1: Асинхронный запуск после каждого этапа.
- FR-6.2: Diff-based: только измененные решения.
- FR-6.3: Fairness score < 85% на измененных -> метка bias-risk.
- FR-6.4: Накопленный score < 80% -> задача tech-debt:bias-audit.

### FR-7: Two-Way Masking
- FR-7.1: Детерминированная токенизация PII -> Token.
- FR-7.2: Token Vault on-prem, AES-256, RBAC.
- FR-7.3: Re-identification только в UI рекрутера.
- FR-7.4: Audit каждого демаскирования (кто, когда, токен).
- FR-7.5: Tokenizer недоступен -> read-only режим, новые скрининги блокируются.

### FR-8: Consent & Retention
- FR-8.1: Отзыв согласия -> hard trigger, немедленная остановка пайплайнов.
- FR-8.2: Purge Pipeline: Git, Vector Index, MCP Logs - SLA < 4 часа.
- FR-8.3: TTL по типам данных (резюме 6 мес, scorecard 12 мес, audit 3 года).
- FR-8.4: Consent coverage - 100% активных кандидатов.

### FR-9: Context Enrichment
- FR-9.1: Метка context-gap -> логирование в Context Provider Queue.
- FR-9.2: MCP-сервер для Gitea/Forgejo - авто-чтение репозиториев, issues, PR.

### FR-10: Cost per Hire
- FR-10.1: Формула: (CU_total x CU_TO_RUB) + (часы ревью x ставка).
- FR-10.2: Порог окупаемости: агент < 0.7 x человек.
- FR-10.3: Отслеживание по типам ролей.

## 2. Нефункциональные требования

| NFR | Требование |
|---|---|
| NFR-1: Latency (фоновый) | p95 <= 15 мин |
| NFR-2: Latency (интерактивный) | p95 <= 5 сек |
| NFR-3: Availability | 99.5% для Gateway |
| NFR-4: Data residency | On-prem для PII и Token Vault |
| NFR-5: Compliance | 152-ФЗ, GDPR Art. 17 |
| NFR-6: Audit | Immutable log, retention 3 года |
| NFR-7: Импортозамещение | GigaChat 3.5 Ultra / Lightning, Ollama |
| NFR-8: Batch efficiency | Экономия CU до 90% при batch 10 |
