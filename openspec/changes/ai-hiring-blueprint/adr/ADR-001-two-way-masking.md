# ADR-001: Two-Way Masking вместо классического NER

## Статус
Accepted

## Контекст
Классическое NER-маскирование необратимо удаляет PII, что приводит к:
- Потере смысла контекста ("работал в <ORGANIZATION> над <PRODUCT>" - бесполезно).
- Ложным срабатываниям на редких технологиях/вузах.
- Невозможности показать рекрутеру полный контекст.

## Решение
Внедрить Anonymization Tokenizer с обратимым маскированием:
- PII -> детерминированный Token.
- Token Vault on-prem, AES-256, RBAC.
- Re-identification только в UI рекрутера.
- Audit каждого демаскирования.

## Последствия
Плюсы:
- Сохраняется смысл контекста для LLM.
- 152-ФЗ compliance.
- Точный audit (кто, когда, какой токен).

Минусы:
- Дополнительный компонент (Token Vault).
- Сложность RBAC.
- Fallback: read-only при недоступности Tokenizer.

## Альтернативы
| Альтернатива | Отклонена |
|---|---|
| NER-маскирование | Необратимо, теряет смысл |
| Полный отказ от PII | Невозможно для найма |
| Шифрование всего | LLM не работает с шифротекстом |
